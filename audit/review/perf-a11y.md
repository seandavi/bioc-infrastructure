# Bioconductor website — performance, accessibility & standards audit

**Date:** 2026-07-25
**Scope:** `bioconductor.org` (homepage, `/install/`, `/help/`, package landing page, biocViews browse, build report) and `support.bioconductor.org` for comparison.
**Method:** Headless Chromium 140 (Playwright 1228 build) driven from Node; CDP `Network` domain for the real waterfall; `PerformanceObserver` (buffered) for LCP/CLS/long tasks; axe-core 4.12.1 for WCAG rule checks; WCAG contrast computed from real `getComputedStyle` values; `curl` for response headers; `gzip -9` for compression-savings estimates. Every number below came from one of those; anything I did not measure is labelled **inferred**.

> **Framing.** This is a volunteer-maintained scientific resource, not a commercial product. I have weighted the recommendations accordingly: server-config one-liners and genuine bugs first, cosmetic Lighthouse-score chasing not at all. Several "classic" perf recommendations are explicitly **not** worth doing here and I say so at the end. The 2024-era redesigned pages are, on the evidence, in good shape — the problems concentrate in server configuration and in machine-generated legacy pages.

---

## Executive summary — the 5 findings that matter

1. **Compression is off for JavaScript, SVG and fonts.** Only `text/html` and `text/css` get gzipped. Everything else ships raw. Measured: the biocViews page transfers **1,396 KB of compressible same-origin assets that gzip to 434 KB — 961 KB wasted on a single page load** (69%). Homepage wastes 208 KB, `/install/` 378 KB. This is a one-line Apache config change and is by far the highest impact/effort ratio in this report.

2. **The site is HTTP/1.1 only**, despite sitting behind CloudFront (which supports h2/h3). Combined with 24 unbundled render-blocking stylesheets in `<head>`, this is severe on a slow link: measured **FCP 11.1 s and load 18.0 s on emulated Slow 4G** for the homepage; biocViews takes **38.3 s to load**. Third-party CDNs on the same pages negotiate h2 — only Bioconductor's own origin is stuck on 1.1. Enabling HTTP/2 is a CloudFront distribution setting, not a code change.

3. **Three uncaught JavaScript errors fire on every single page**, plus a fourth on package pages. All trace to `assets/js/bioconductor.js`, which runs biocViews-specific code unconditionally site-wide. Separately, `layouts/components/sitescripts.html:20` contains a **malformed regex literal that is a hard `SyntaxError`**, silently killing the mirror `<base href>` logic on every package landing page.

4. **The biocViews package table is close to unusable by keyboard.** `assets/js/bioc_views.js` puts `tabindex="0"` on every `<td>`, producing **12,169 tab stops** on one page, and adds redundant ARIA roles that break the table semantics — **2,418 `aria-required-parent` violations (critical)**. Removing the hand-written ARIA and tabindex attributes fixes both; native `<table>` semantics are already correct.

5. **The machine-generated legacy pages fail WCAG basics that the redesigned pages pass.** The build report has **no `lang` attribute, no viewport meta, 7,147 contrast violations, 62 tables with no `<th>`, 4 unlabelled checkboxes and 2,423 inline event handlers**. `support.bioconductor.org` **renders in quirks mode (no doctype)**, has no `lang`, no `<h1>`, and 7 images with no `alt`. These are generated by scripts/templates outside this repo, so fixes need to land in the generators.

**Credit where due:** the redesigned pages are genuinely good. axe-core finds only **2–3 moderate violations** on the homepage, `/install/`, `/help/` and package pages. Every image has `alt` text, heading structure is nearly clean, landmarks exist, CLS is negligible, the body font is Atkinson Hyperlegible (an accessibility-designed typeface), and the layout reflows to 320 px with no horizontal scrolling. The problems are in server config and in old generated HTML, not in the new design work.

### 1.3 Compression — the single biggest win

Verified by `curl -H 'Accept-Encoding: gzip, deflate, br'` against the live origin:

| Content-Type | `Content-Encoding` returned | Verdict |
|---|---|---|
| `text/html` | `gzip` | OK |
| `text/css` | `gzip` | OK |
| `text/javascript` | **none** | Broken |
| `image/svg+xml` | **none** | Broken |
| `font/ttf` | **none** | Broken |

**Likely root cause (inferred):** the Apache `mod_deflate` type list on the origin almost certainly lists `application/javascript`, but Apache 2.4.52 on Ubuntu serves `.js` as `text/javascript` (per the modern `mime.types`), so the filter never matches. `image/svg+xml` and font types are simply absent from the list. The server config is not in this repo (only `assets/.htaccess`), so this needs a change on the origin host or `AddOutputFilterByType` added to `assets/.htaccess`.

### 1.4 HTTP version and the cost of HTTP/1.1

`curl --http2` negotiates **`http/1.1`** against both `bioconductor.org` and `support.bioconductor.org`. Across all measured page loads, CDP reported the protocol as: **`http/1.1` ×283, `h2` ×41** — every `h2` request went to a third-party CDN (googletagmanager, cdnjs, code.jquery, fonts.gstatic). No `Alt-Svc` header, so no HTTP/3 either.

Impact, measured with CDP `Network.emulateNetworkConditions`:

| Profile | Page | FCP | LCP | Load |
|---|---|---:|---:|---:|
| Fast 4G (4 Mbps, 150 ms RTT) | Homepage | 848 ms | 848 ms | 2,217 ms |
| Fast 4G | biocViews | 1,196 ms | 2,088 ms | 5,129 ms |
| **Slow 4G (400 kbps, 400 ms RTT)** | **Homepage** | **11,100 ms** | **11,100 ms** | **18,017 ms** |
| **Slow 4G** | **biocViews** | **10,792 ms** | **10,808 ms** | **38,292 ms** |

An 11-second first paint on the homepage is what a user on a poor connection actually experiences — 35 render-blocking-ish assets serialised over six HTTP/1.1 connections at 400 ms RTT. Enabling h2 on the CloudFront distribution multiplexes them onto one connection and is a settings toggle. This is the highest-value change after compression, and it requires no code.

### 1.5 Render-blocking resources

Measured by parsing the served homepage HTML and classifying by document position:

- **24 `<link rel=stylesheet>` in `<head>`** — all render-blocking. 23 same-origin + 1 from `cdnjs.cloudflare.com`.
- **Page-specific CSS is loaded on every page**: `pages/home.css`, `pages/get-started.css`, `pages/learn-and-dev.css`, `pages/about.css`, `pages/packages.css`, `pages/orcid.css` all load on the homepage regardless of relevance.
- **11 `<script>` at end of `<body>`**: 1 async (gtag), 1 inline, **9 blocking**. Because they are at the end of `<body>` they do not block first paint — this is why unthrottled FCP is good, and it is worth preserving.
- The one third-party stylesheet in `<head>` (highlight.js theme) blocks rendering on a connection to a host the page otherwise wouldn't need. See §2.

**highlight.js is loaded on pages that have no code to highlight.** The served homepage contains **zero `<pre>` elements**, yet `layouts/components/sitescripts.html:42` loads `highlight.min.js` (35.1 KB) plus its theme CSS (1.1 KB) from `cdnjs.cloudflare.com` unconditionally, site-wide.

### 1.6 Images

| Format | Unique files across all pages | Bytes |
|---|---:|---:|
| SVG | 30 | 471 KB |
| PNG | 10 | 265 KB |
| JPEG | 4 | 7 KB |
| GIF | 1 | 3 KB |

- **No WebP or AVIF anywhere.** Given SVG dominates the byte count, this matters less than it usually would — the real SVG problem is that they aren't gzipped (§1.3), not that they're the wrong format.
- Three decorative SVGs are extraordinarily large for what they are: `Step 3 quote.svg` **215 KB**, `Step 2 quote.svg` 53 KB, `Step 1 quote.svg` 36 KB. **Inferred:** these are almost certainly exported artwork with embedded raster data or un-simplified paths; running them through SVGO would likely cut them dramatically on top of gzip. Not verified — I did not inspect their internals.
- **Missing dimensions:** homepage has 25 images, **21 with no `width`/`height` attributes and no CSS `aspect-ratio`**; `/install/` 12 of 12; `/help/` 10 of 10; DESeq2 16 of 16. In practice measured CLS is still low (0.002–0.067) because most are small or in fixed containers, so this is a latent risk rather than an active defect — but it is what makes the DESeq2 page the worst at **CLS 0.067**.
- **4 images on the homepage are served at more than 2× their displayed size** (naturally-sized bitmaps scaled down in CSS).

### 1.7 Fonts

- Two faces: `AtkinsonHyperlegible-Regular.ttf` (52 KB) and `-Bold.ttf` (53 KB), self-hosted from `/style/fonts/`. **Good choice** — Atkinson Hyperlegible is designed for low-vision readability.
- **Served as raw TTF, not WOFF2.** WOFF2 would be substantially smaller; even plain gzip takes them to 28 KB / 29 KB (measured). Currently neither is applied — **106 KB of font on every page**.
- **`font-display` is not set on either `@font-face`** (measured: `(not set)`, i.e. `auto` → block). This risks a flash of invisible text; `swap` is a one-word fix in `assets/style/base/fonts.css`.

### 1.8 Caching

| Resource | `Cache-Control` | `ETag` |
|---|---|---|
| `/` (HTML) | `max-age=600` | yes |
| `/packages/.../DESeq2.html` | `max-age=600` | yes |
| `/js/bioconductor.js` | `max-age=600` | yes |
| `/style/base/layout.css` | **none** | yes |
| `/images/logo/svg/Logo.svg` | **none** (`.htaccess` sets `max-age=30`) | yes |
| build report | `max-age=600` | yes |

- **No asset is cached for more than 10 minutes; CSS and images have no `Cache-Control` at all** and fall back to heuristic caching. Every repeat visitor re-validates essentially the whole site.
- **No content hashing / versioned filenames anywhere**, which is *why* the TTLs must stay short — you cannot safely cache `layout.css` for a year if deploying overwrites it in place. So "just raise max-age" is not safe on its own; see the structural fix list.
- `assets/.htaccess:34-36` sets SVG to `max-age=30`. For logos and icons this is pointlessly aggressive.
- By contrast `support.bioconductor.org` does this correctly: hashed filenames (`output.b3e21268cb4d.css`) with `max-age=315360000`. Worth copying the pattern. (It does emit **two conflicting `Cache-Control` headers** — `max-age=315360000` and `public` on separate lines — which is a minor bug.)
- CDN: CloudFront confirmed on `bioconductor.org` (`X-Cache: Hit from cloudfront`, `Via: ... .cloudfront.net`, PoP `DEN53-P4`). `support.bioconductor.org` is origin-direct nginx, no CDN.

**Findings:**

- **`gtag.js` is 151 KB per page — the single largest script on the site**, larger than all nine of Bioconductor's own scripts combined (~124 KB uncompressed). It is `async`, so it doesn't block rendering, but it is a real cost for every visitor and it sends every pageview to Google. For a publicly funded scientific resource, a self-hosted analytics option (GoatCounter, Plausible, or simply parsing the existing Apache logs) is worth considering. Flagging as a policy question, not a defect.
- **No Subresource Integrity on any external script.** Measured: `integrity=` appears **0 times** in the served homepage and DESeq2 HTML. Five third-party origins can execute arbitrary JS in the page.
- **Protocol-relative URLs.** `layouts/components/sitescripts.html:18,42` and the highlight.js stylesheet use `//host/...` rather than `https://`. This is a legacy pattern from the mixed http/https era; it should simply be `https://`. (No active mixed-content: the pages load over HTTPS, so these resolve to HTTPS in practice.)
- **`ajax.aspnetcdn.com` is Microsoft's retired Ajax CDN.** It still answered (HTTP 200, 70,857 bytes) when tested, but it is a deprecated service that Microsoft has announced the shutdown of. biocViews' package table will break outright when it goes away. This is a live reliability risk with a trivial fix (self-host the 21 KB file).
- **Seriously outdated libraries with known CVEs:**

  | Library | Version | Released | Loaded from | Note |
  |---|---|---|---|---|
  | jQuery | **1.6.4** | Sep 2011 | self-hosted `/js/jquery.js` | affected by CVE-2015-9251, CVE-2019-11358, CVE-2020-11022/11023 (inferred from version; not exploit-tested) |
  | jQuery | **1.5.1** | Feb 2011 | `ajax.googleapis.com` | package landing pages only |
  | jQuery UI | 1.10.4 | 2014 | `code.jquery.com` | biocViews |
  | jsTree | 1.0 | ~2011 | self-hosted | biocViews |
  | DataTables | 1.9.4 | 2012 | `ajax.aspnetcdn.com` | biocViews |

  These are XSS-class issues that require attacker-controlled input reaching jQuery sinks. On a mostly-static site the practical exposure is limited, but package landing pages render maintainer-supplied metadata, so it is not zero. **Inferred severity — I did not attempt to demonstrate an exploit.**

### 3.2 Colour contrast

I computed WCAG ratios directly from `getComputedStyle` for every distinct text style, then **manually verified every reported failure** against the element's background chain.

**Important correction to my own first pass:** my naive checker initially flagged the homepage "Get started" button, the `Bioc2026` announcement link, and the biocViews selected-node highlight as 1:1 failures. **All three are false positives** — those elements have `linear-gradient` backgrounds with `background-color: transparent`, which a naive parent-walk misreads as white-on-white. Verified by dumping `background-image` for each. Hand-computing against the real gradients:

- Announcement link (black on the teal→green gradient): **5.08:1 to 6.49:1** — passes AA.
- Hero "Get started" button (white on the same gradient): **3.23:1 to 4.14:1** at 19.2 px/700, which qualifies as large text (≥18.66 px bold, threshold 3.0) — **passes, but marginally**. It would fail if the button text were ever made smaller or lighter-weight. Worth a note in the design system rather than a fix.

axe-core agrees: **0 contrast violations on the homepage, `/install/`, `/help/` and package pages.** Contrast on the redesigned pages is fine.

### 3.3 Structure, landmarks and navigation

| Check | Homepage | install | help | pkg | biocViews | build | support |
|---|---|---|---|---|---|---|---|

| **Skip link** | **none** | **none** | **none** | **none** | **none** | **none** | **none** |

- **No skip link on any page.** With 104 focusable elements on the homepage — and a nav block repeated before the content on every page — a keyboard or screen-reader user must traverse the entire header every time. `assets/style/base/layout.css:52` **already defines an `.sr-only` utility**, so this is one line of HTML in `layouts/default.html`.
- **Duplicate `<meta name="viewport">`** on all bioconductor.org pages, from `layouts/_sitehead.html:3` and `:7` — two slightly different values (`initial-scale=1.0` vs `1`). Harmless in practice (last wins) but invalid.
- **The build report has no viewport meta at all**, so it is not mobile-responsive in any meaningful sense.
- `landmark-unique` fires on every redesigned page: `<nav class="header-nav">` is not distinguished from the other nav landmarks (up to 9 on the homepage). Fix is an `aria-label` on each.
- Heading skips: `/install/` jumps h1→h4 ("1. Install R"), and h3→h5 twice ("Updgrading Installed Bioconductor Packages" — also a **typo** in the heading text, "Updgrading"; worth fixing while there).

### 3.4 Keyboard and focus

- **Focus visibility is mostly fine.** I tabbed 12 elements deep on four pages and read the computed outline each time: nav links get `outline: auto 3px`, which is visible.
- **One real gap: the site search box.** `assets/style/sections/header.css` contains `.search-bar { ... outline: none; ... }` — measured `outline-style: none` when focused, with no `box-shadow` or border change to replace it. The search input is **the only element on the page with no focus indicator**. This is a WCAG 2.4.7 failure on a primary navigation control.
- Site-wide there is **1 `outline: none` rule and 0 `:focus-visible` rules** on bioconductor.org — so there's no modern focus-styling layer to fall back on. (support.bioconductor.org has 13 `outline:none` rules and 126 `:focus` rules from its Semantic UI bundle.)
- **No positive `tabindex` values** and **no focusable content inside `aria-hidden`** anywhere — both good.
- **biocViews is the exception and it is severe:** **12,169 focusable elements**. `assets/js/bioc_views.js:54-61` emits `tabindex="0"` on every one of the 9,672 `<td>` cells. Tabbing through the package table is effectively impossible. Table cells should not be focusable; the links inside them already are.

### 3.5 ARIA

- The redesigned pages use **almost no ARIA at all** — measured `roles: {}` on homepage, install, help and package pages. For largely static content this is correct and much safer than over-annotating.
- **biocViews is the opposite and it's broken.** `assets/js/bioc_views.js:39-61` hand-writes `role="table"`, `role="row"` (×2,420), `role="cell"` (×9,672), `role="columnheader"` (×8) onto a real `<table>`, and DataTables wraps it in `role="grid"`. Result: **2,418 `aria-required-parent` violations** (rows whose parent has no `rowgroup` role) and **2 `aria-required-children`**. The redundant roles *override* correct native table semantics and replace them with broken ones.
  **The fix is deletion, not addition:** remove the `role` and `tabindex` attributes from `bioc_views.js`. A plain `<table><thead><tr><th>` is already fully accessible. This single change resolves the two critical violations *and* the 12,169-tab-stop problem.
- 4 `<th>` elements on biocViews are empty (`empty-table-header`).

### 3.6 Tables

| Page | Tables | No `<th>` | No `<caption>` | `<th>` without `scope` |
|---|---:|---:|---:|---:|
| DESeq2 landing | 4 | **4** | 4 | 0 |
| biocViews | 2 | 0 | 2 | 0 |
| Build report | **62** | **62** | 62 | 0 |

- The **build report's 62 tables have no `<th>` at all** — every one is a bare `<tr><td>` grid. For a screen-reader user this is 62 unlabelled data grids and is the page's most serious structural failure after the missing `lang`.
- The DESeq2 landing page's 4 tables (details, dependencies, import lists) also lack headers. **Inferred:** these are probably being used for layout rather than data, in which case the right fix is CSS, not adding `<th>`. Worth a look before adding headers reflexively.
- Captions are missing everywhere. Lower priority than headers.

### 3.7 Forms

- Redesigned pages: **all form fields are properly labelled** (0 unlabelled across homepage, install, help, DESeq2).
- **Build report: 4 unlabelled checkboxes** (`timeout_checkbox`, `error_checkbox`, `warnings_checkbox`, `ok_checkbox`) — these are the filter controls, i.e. the page's only interactive feature, and they are unusable by screen reader. Also `target-size` failures (below 24×24 px).
- **biocViews: 1 unlabelled control** (`tree-toggler`).
- **support: the search box (`query`) is placeholder-only**, no accessible name.

### 3.8 Link text

Measured across all pages: **0 "click here" / "read more" style links**, 1 borderline "Learn More" on the homepage, **0 empty links** and **0 bare-URL links** on bioconductor.org. Link text quality on the main site is genuinely good.

- DESeq2 page has **3 bare-URL links** (rendered from package metadata).
- **support has 8 links with no discernible text** (`link-name`) — icon-only pagination buttons and the logo link, whose `<img>` has no `alt`.
- **6 links per page open in a new tab (`target="_blank"`) with no warning** to the user in text or `aria-label`. Minor (WCAG 3.2.5, AAA) but easy to address.

### 3.9 Motion, zoom, and touch targets

- **Reflow (1.4.10) passes.** At a 320 px viewport, `scrollWidth == clientWidth` on homepage, DESeq2 and biocViews — **no horizontal page scrolling**. At 640×512 (≈200% zoom) likewise. A couple of homepage event cards measure 328 px against a 320 px viewport (8 px overflow) but are clipped rather than causing a scrollbar. Good result, and better than most sites of this age.
- **Motion:** no `prefers-reduced-motion` media query in the stylesheets (**inferred** from the absence of `focus-visible`-era CSS generally); animations present are CSS transitions on hover, which are low-risk. Not a practical problem.
- **Touch targets (2.5.8, new in WCAG 2.2):** axe reports **0 violations on the homepage at 375×812**, because most small targets are inline links within text blocks, which the success criterion exempts. My raw measurement (58 targets under 24 px) overstates the problem — **axe's number is the correct one.** Genuine failures are confined to **build report (4)** and **support (6)**, both non-exempt form controls and icon buttons.

## 4. Standards and hygiene

### 4.1 JavaScript errors — present on every page

Captured via Playwright `pageerror` with stack traces:

| Error | Origin | Pages |
|---|---|---|
| `TypeError: Cannot read properties of undefined (reading 'test')` | `assets/js/bioconductor.js:36` in `checkNav()` | **all** |
| `TypeError: Failed to execute 'appendChild' on 'Node': parameter 1 is not of type 'Node'` | `assets/js/bioconductor.js:156` in `wrapChildDivs()` | **all** |
| `TypeError: Cannot read properties of null (reading 'addEventListener')` | `assets/js/bioconductor.js:173` | **all** |
| `SyntaxError: Invalid or unexpected token` | `layouts/components/sitescripts.html:20` (inline) | package landing pages |
| `TypeError: Cannot read properties of null (reading 'offsetTop')` | (biocViews-specific) | biocViews |
| `ReferenceError: Prism is not defined` | support's own bundle | support |

**Root causes — one shared pattern.** `bioconductor.js` contains biocViews-page-specific code that runs unconditionally on every page:

- **`checkNav()` (line 36):** `nav_elements` is a 4-element array of regexes (lines 24-29), but the function iterates `document.querySelectorAll(".nav-links a")`, which returns more links than that. `nav_elements[index]` is `undefined` past index 3 → `.test` throws. The active-nav-underline feature is broken for every link past the fourth.
- **`wrapChildDivs()` (line 156):** unconditionally calls `appendChild(lengthDiv)` where `lengthDiv = document.getElementById("biocViews_package_table_length")` — an element that only exists on biocViews. `null` elsewhere → throws.
- **Line 173:** `document.getElementById("tree_outer").addEventListener(...)` — same problem, `tree_outer` is biocViews-only.

The lazy correct fix is a guard at the top of each function (`if (!el) return;`), not a guard at each call site.

- **`sitescripts.html:20` is a genuine syntax error:**

  ```js
  if (!window.location.href.match(/bioconductor\.org|\/\/localhost|amazonaws\.com/|cloudfront\.net/i)) {
  ```

  The regex literal **terminates at `amazonaws\.com/`**; the trailing `|cloudfront\.net/i` is parsed as expression garbage. The whole `<script>` block fails to parse, so `document.write('<base href="//www.bioconductor.org"/>')` **never executes**. The mirror-site base-href feature is silently dead. The intended literal is `/bioconductor\.org|\/\/localhost|amazonaws\.com|cloudfront\.net/i` — the stray `/` after `com` should not be there.

### 4.2 HTML validity

- **Duplicate `<meta name="viewport">`** on all bioconductor.org pages (`layouts/_sitehead.html:3` and `:7`).
- **Duplicate ID `svn-source`** (×2) on the DESeq2 landing page.
- **Duplicate IDs on support:** `login-opts`, `menu-header`, `logo` (×2 each).
- **support.bioconductor.org has no doctype** → **quirks mode**. This changes box-model and layout behaviour and is the most impactful validity bug found.
- **No deprecated elements** (`<center>`, `<font>`, `<big>`, `<marquee>`, …) on any page — measured `{}` everywhere. **No deprecated presentational attributes** either. Genuinely clean; better than expected for a site of this vintage.
- Every page has exactly one `<title>` and one charset declaration. All bioconductor.org pages have a meta description; build report and support do not.
- **2,423 inline `on*` event handlers** and **2,471 inline `style` attributes** on the build report; 108 inline styles on biocViews; 6 inline handlers on the DESeq2 page. This is what makes a Content-Security-Policy hard to adopt (see below).

### 4.3 Security headers

| Header | bioconductor.org | support.bioconductor.org | contributions.bioconductor.org |
|---|---|---|---|
| `Strict-Transport-Security` | **absent** | **absent** | (GitHub Pages) |
| `Content-Security-Policy` | **absent** | **absent** | — |
| `X-Content-Type-Options` | **absent** | `nosniff` | — |
| `X-Frame-Options` | **absent** | `DENY` | — |
| `Referrer-Policy` | **absent** | `same-origin` | — |
| `Permissions-Policy` | **absent** | **absent** | — |
| Server banner | `Apache/2.4.52 (Ubuntu)` | `nginx/1.18.0 (Ubuntu)` | `GitHub.com` |

`bioconductor.org` sends **no security headers whatsoever**. `support.bioconductor.org` (Django/Biostar) sets three sensible ones by default.

- **`X-Content-Type-Options: nosniff`, `Referrer-Policy`, and HSTS are three lines** in the Apache config with essentially no compatibility risk. Worth doing.
- **CSP is genuinely hard here** and I would not recommend attempting it soon: 2,423 inline event handlers on the build report and 5 third-party script origins mean any useful policy would need `unsafe-inline` and a long allowlist, which buys little. Revisit only after the inline handlers are gone.
- **`master.bioconductor.org` is publicly reachable** and serves the site directly, bypassing CloudFront. It is documented as the origin in `README.cloudfront.md`. **Inferred:** this is probably intentional for debugging, but it does mean the origin is directly addressable and un-cached; worth confirming it's meant to be public.
- **No mixed content** detected on any page.

## 6. What I deliberately do *not* recommend

Because this is a volunteer-maintained project, some standard advice is not worth the maintenance burden:

- **Don't bundle/minify the 24 stylesheets.** They total 27 KB. Once HTTP/2 is on (#2), 24 small files cost almost nothing, and a build step for CSS concatenation is ongoing maintenance for a marginal gain. Fix the protocol, not the file count.
- **Don't move to a JS framework or SSG rewrite.** The nanoc setup works and the redesigned pages measure well.
- **Don't chase a Lighthouse 100.** Unthrottled FCP is already ~250 ms; the meaningful wins are compression and h2, both of which are server settings.
- **Don't attempt CSP yet.** With 2,423 inline handlers on the build report, any workable policy needs `unsafe-inline` and provides little real protection. Revisit after #21.
- **Don't convert SVGs to WebP/AVIF.** SVG is the right format here; they just need gzip and SVGO.

## 7. Measurement caveats

- All timings are single runs from one location (CloudFront PoP `DEN53-P4`, Denver) on a fast wired connection, in headless Chromium with a warm CDN. Unthrottled numbers are best-case; the Slow-4G figures in §1.4 are the more representative ones.
- Bytes are CDP `encodedDataLength` — actual wire bytes including headers.
- Compression savings use `gzip -9`, so they are conservative: brotli would do slightly better, and the CDN would apply it at the edge.
- axe-core catches roughly 30-40% of WCAG issues automatically. **No manual screen-reader testing was performed** — findings here are automated plus targeted manual verification of contrast, focus order (12 tab stops per page on 4 pages), and reflow. A real screen-reader pass on the build report and biocViews would likely find more.
- Library CVE associations are **inferred from version numbers**; I did not test for exploitability.
- I audited the **live site**; the local clone at `bioc-site-src` was used to trace findings to source files. If the clone is behind production, file line numbers may have shifted.
